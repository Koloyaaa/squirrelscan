## What this rule detects

A page can answer 200 with its title and meta intact while the file that makes it work returns an error. The common cause is a deploy: cached HTML still references hashed bundles such as `/assets/app.3f9a1c.js`, and the new release deleted them. In a browser the page is unstyled or its buttons and menus never start.

This rule reads the scripts, stylesheets and fonts the crawl already fetched. It makes no extra requests and does not render the page, so it runs in every audit, including HTTP-only ones. Images are not covered here: [images/broken-images](/rules/images/broken-images) reports them.

## What squirrel checks

The rule is site-wide. It emits one finding per resource URL, listing the status and every page that references it, rather than one per page.

- **Error:** a first-party script or stylesheet (on the site's host or a subdomain) answers 4xx or 5xx. Check name `broken-resources`, with a message such as `1 first-party script or stylesheet(s) answer with an error status`.
- **Warning:** a third-party script or stylesheet answers 4xx or 5xx, a font answers 4xx or 5xx, or a request fails at the network level (DNS, TLS, timeout). Check name `unreachable-resources`. Network failures are often transient, which is why they warn rather than fail.
- **Not broken:** a resource that answers 429 or 430 (throttled), or 503, is reported as unverified information. The origin asked squirrel to come back later, so the status says nothing about the file. Check name `unverified-resources`.
- **Partial check:** when a fetch was skipped (the asset budget ran out, or a host was tarpitting) or a kind of resource was not measured, the result says so with an information note named `unchecked-resources`. A pass in that case covers only the resources that were checked.
- **Pass:** every checked resource answers below 400. Message: `All N checked script, stylesheet and font resource(s) load`.

Only resources the pages reference are checked. Scripts and stylesheets are read from the same host or its subdomains, so a third-party resource is checked only when the crawl fetched it.

## How to fix it

Redeploy the missing file, or change the reference so the page points at a bundle that exists. Keep hashed assets from the previous release online for as long as cached HTML may still reference them. A cached page that points at a file the origin no longer serves fails the same way as a stale link.

```html
<!-- Points at a bundle the last deploy deleted -->
<script src="/assets/app.3f9a1c.js"></script>
```

For a third-party script or font, check the provider's status page, or remove the reference if the service has gone.

## Enable / disable

### Disable this rule

```toml squirrel.toml
[rules]
disable = ["reliability/broken-resources"]
```

### Disable all Reliability rules

```toml squirrel.toml
[rules]
disable = ["reliability/*"]
```

### Enable only this rule

```toml squirrel.toml
[rules]
enable = ["reliability/broken-resources"]
```

`enable` replaces the default `["*"]`, so this is the only rule selected. Leave `disable` out: a rule that matches any `disable` pattern is skipped even when `enable` names it.
