title: "Forms that lose submissions: unnamed fields and dead actions"
description: "A form can look perfect and still drop every submission. squirrel checks that each field has a name the browser sends, and that each form action answers."
---

## What this rule detects

Two faults lose form submissions without any visible error. The first is a field with no `name`. The browser shows it, the visitor fills it in, and then the browser leaves it out of the request, because only named controls are submitted. The usual cause is a copy-pasted field or a refactor that moved `name` to `id`.

The second is an `action` that goes nowhere. It may be an old endpoint that now returns 404, a staging or localhost host that shipped by accident, or a `mailto:` link that only opens the visitor's mail client. The visitor sees a success message, and the site owner finds out weeks later.

The rule reads the forms the crawl already parsed. It checks each form's fields in the page, and it checks each action against the crawl or, where needed, with a request.

## What squirrel checks

The rule is site-wide. Each finding lists the form and the pages it appears on.

- **Field with no name, in a form that posts to an action:** a warning, check name `unnamed-form-fields`. The message names the field, such as `input#email (email) in form[action="/contact"]`.
- **Field with no name, in a form with no real action** (no `action`, or `action="#"`): information, check name `unnamed-form-fields-no-action`. A script may read the field by `id` or from component state, so this is not reported as broken.
- **First-party action answers 404 or 410:** an error, check name `dead-form-action`. Every submission to it is lost.
- **Action points at a staging, preview, development or localhost host:** a warning, check name `non-production-form-action`. The same host classification as [content/dev-leakage](/rules/content/dev-leakage) is used. No request is sent to these hosts.
- **Action uses `mailto:`:** a warning, check name `mailto-form-action`. It opens the visitor's mail client, so most submissions are lost.
- **Action answers 5xx, fails at the network level, or a third-party action answers 404 or 410:** a warning, check name `unreachable-form-action`.
- **Action answers 429, 503 with `Retry-After`, or a WAF challenge:** information, check name `unverified-form-actions`. The status says nothing about the handler, so it is not reported as broken.
- **Action not checked:** information, check name `unchecked-form-actions`. The message says why: passive probing sends no requests, the probe budget ran out, or external link checking is off.
- **Pass:** every form names its fields and its actions answer. Message: `All N form(s) name their fields and their actions answer`.

Fields that are never sent are not reported: `submit`, `button`, `reset` and `image` controls, disabled controls, controls inside a `<template>`, and controls whose `form` attribute names a different form. A control outside any `<form>` that names one with `form="id"` is judged as part of that form.

### How actions are checked

The rule never submits a form and never sends a `POST`. It checks an action in this order:

1. A `mailto:` action, or a staging, preview, development or localhost host, is reported from the URL alone. No request is sent.
2. A same-site action the crawl already fetched uses the crawl's status. No request is sent.
3. Any other same-site action is requested only when the probe level is `active` or `aggressive`. The request is a `HEAD`, and a `GET` follows only when `HEAD` returns 405 or 501, or fails at the network level. Each distinct action URL is probed at most once.
4. A third-party action (a form service such as Formspree or HubSpot) is requested only when external link checking is on. It is probed the same way as step 3.

Under passive probing, steps 3 and 4 send nothing, and the result says the action was not checked.

A plain `http:` action is left to [security/form-https](/rules/security/form-https), which reports insecure submission. This rule does not probe it.

## How to fix it

Give every input, select and textarea a `name` that the handler reads. An `id` is for the label and the script, and it is not sent.

```html
<!-- Shown and filled in, but never sent: no name -->
<input id="email" type="email">

<!-- Sent as email=... -->
<input id="email" name="email" type="email">
```

For an action that answers 404 or 410, point the form at the endpoint that exists, or remove the form. Replace a staging or localhost action with the production URL before release. Replace a `mailto:` action with a handler that stores or sends the submission.

## Enable / disable

### Disable this rule

```toml squirrel.toml
[rules]
disable = ["reliability/broken-forms"]
```

### Disable all Reliability rules

```toml squirrel.toml
[rules]
disable = ["reliability/*"]
```

### Enable only this rule

```toml squirrel.toml
[rules]
enable = ["reliability/broken-forms"]
```

`enable` replaces the default `["*"]`, so this is the only rule selected. Leave `disable` out: a rule that matches any `disable` pattern is skipped even when `enable` names it.
