The `[classifier]` section controls the page classifier, a small model called Treetop that is bundled with squirrel.

## What it does

When a finding names a link, squirrel can say where on the page that link sits: the footer, the navigation, the pagination, a related-content block. Most of that comes from the page's own markup (landmark tags, ARIA roles, comment threads). Plenty of pages have none of it, so the classifier looks at the page structure and fills the gap.

- It runs on your machine. There is no network call and no credit cost.
- The markup always wins. A landmark or a comment thread in the page is never overridden, and comment threads are only ever read from markup.
- It answers only when it is confident, using a per-class bar chosen for precision. An unsure link keeps no section.
- It also stores a page type for each page (article, product, docs, legal and so on) for later rules.
- The model is about 9 MB, loaded the first time a page is classified. Commands that never audit never read it.

Today `links/broken-links` uses it: an item reads `https://example.com/old (404), linked in the pagination`. See [links/broken-links](/rules/links/broken-links) for the sections and phrases.

## Configuration

```toml
[classifier]
enabled = true
```

## Options

### `enabled`

**Type:** `boolean`
**Default:** `true`

`false` switches the classifier off. Link sections then come from page markup alone, and no classification is stored.

For one run, `--no-classifier` does the same:

```bash
squirrel audit https://example.com --no-classifier
```

## Check that it loads

`squirrel self doctor` reports the bundled artifact, the featurizer version it was built for and how long it took to load:

```text
[OK] Page classifier: artifact v1 (sha256 09a76063001b, 8.2 MB), featurizer v2.2.0, region+pageType+section heads, loaded in 19 ms
```

A warning means the model could not be used. Audits still run and link sections fall back to page markup.
